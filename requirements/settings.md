| SET-04 | backlog | The installation has a public address, with optional extra addresses, that feed links and Google use. | — |
| SET-04.a | backlog | A public address given at installation is saved once. After that the saved address is the only one used (DEP-05), so clearing it leaves it cleared. | — |
| SET-04.b | backlog | Until a public address is set, setup reports Not set yet and points to Public address settings, the subscription page warns that the address is missing and, before the first destination is configured, setup suggests an address taken from the request. Once an address is set, none of these appear; a setup field can be filled from the address used to open the page. | — |
| SET-04.c | backlog | A bare public host becomes an HTTPS address, with lowercase scheme/host, no trailing slash and no default port; a supplied path is preserved. | — |
| SET-04.d | backlog | The saved public address is the one used in feed links; Google's callback address follows PGAP-01. | — |
| SET-04.e | backlog | An address is not a valid public address (UIC-19) when it is not an http or https URL, has no host, has a query, parameters, a fragment, embedded credentials, whitespace or an invalid port, is longer than the length in DEF-01, or has a single slash after the scheme. | — |
| SET-04.f | backlog | Clearing the public address removes it. An installer default that only works on the local machine or network (HTTP to a private IP address or localhost) is not a public address. | — |
| SET-04.g | backlog | The page warns when it is opened through a host that is not a public host of the installation or one of the user's own networks (ACC-07), naming the host used and the configured host. | — |
| SET-04.h | backlog | Each extra public address is validated on its own; blank extras are left out and an invalid extra is not valid (UIC-19). | — |
| SET-04.i | backlog | Domains can be saved independently of Login settings. | — |
| SET-04.j | backlog | Removing or clearing public-address rows leaves one main address field, with its value cleared when removed; removing the extra row leaves the main address row. | — |
| SET-04.k | backlog | Effective public addresses are deduplicated, with the main address first and valid extras afterward. | — |
| SET-04.l | backlog | The Domains item has a button msg:thisPage that fills the address the page is opened at; the add-address button is only on the last row; an empty main address shows msg:notSetYet. | — |
| SET-04.m | backlog | After the main public address changes while Google sign-in is set up, the page opens Settings with a prompt to correct the redirect address in Google (PGAP-01). | — |
| SET-04.n | backlog | A saved public address that no longer passes the checks of SET-04.c and SET-04.e is treated as not set. | — |
| SET-05 | backlog | The app checks for newer versions and can update itself, and shows what is happening. | — |
| SET-05.a | backlog | Update checks run on the chosen schedule (hourly, weekly, monthly or never; the default and values are in DEF-01). Never turns automatic checks off. | — |
| SET-05.b | backlog | Stable installations check stable releases rather than a newer beta; beta installations check beta releases and can advance to the resulting stable release. A pinned non-beta release selects stable, while a pinned beta selects beta. | — |
| SET-05.c | backlog | A version is major.minor.patch with an optional -beta.N (0.2.8-beta.46). A release is newer than its betas, and betas compare by their number. A version that does not follow this form, and an unknown installed version, cannot be compared, so it is not offered as newer. | — |
| SET-05.d | backlog | A check, scheduled or Check now, reports Up to date when nothing newer is available; otherwise it offers the newer version with links to the running and available releases, and keeps the running-version information. A failed check, including an invalid offer, reports Couldn't check and its cause and keeps the last offered version. | — |
| SET-05.e | backlog | Changing update channel clears the previous channel’s check result. | — |
| SET-05.f | backlog | Updates reports Not checked before the first check and shows the next scheduled check time. | — |
| SET-05.g | backlog | An available version is announced in History once, however many times it is checked for. | — |
| SET-05.h | backlog | Update now is offered only when an update is available, the updater service is ready and the installation is not pinned to an exact image version; otherwise the page shows installer guidance. Automatic updating, which the user can turn on or off, follows the same conditions, and a pending update is requested once. | — |
| SET-05.i | backlog | Update now requests the offered app image through the configured updater using its authorization token; it does not request unrelated images. | — |
| SET-05.j | backlog | Starting an update records an activity message naming its target version. | — |
| SET-05.k | backlog | An update that cannot reach the updater, or whose token the updater rejects, reports Update failed and the cause. | — |
| SET-05.l | backlog | A running update reports Downloading; once the running version changes, the page identifies the new release and removes the obsolete update offer. | — |
| SET-05.m | backlog | A running update is remembered for the time in DEF-01, and only for the version it started from; after that, or once the running version has changed, it is no longer shown as running. | — |
| SET-05.n | backlog | While an update is applying, every open client shows its progress, Downloading and then Restarting, including a client that did not start it; each reconnects when the app is back, refreshes after the time in DEF-01, and shows the new release with its Settings context kept (UIC-13). | — |
| SET-05.o | backlog | Reopening Updates shows the current saved update-check frequency and auto-update preference, including a change made on another client. A change that fails to save leaves the previous value in effect and shows it. | — |
| SET-05.p | backlog | When nothing newer is available the Updates status reads the running version itself (for example "v1.2.3"), not only "Up to date". | — |
| SET-05.q | backlog | The newest version is read from the project's published version file for the update channel; a request names the client SuiteStream and the running version and nothing else. | — |
| SET-05.r | backlog | An update check ends after the time in DEF-01 and follows redirects; it succeeds only on HTTP 200 with a valid version, and on the stable channel when that version is a stable release. | — |
| SET-05.s | backlog | The background checker first waits the time in DEF-01 after start, then waits until the next check is due but never less or more than the limits in DEF-01; a failed round is logged as a warning and never stops the checker. | — |
| SET-05.t | backlog | When a newer version exists the page header shows msg:versionIsAvailableShort ({v} is the version), linked to its release notes, beside the Update now button when SET-05.h offers it. | — |
| SET-05.u | backlog | Automatic updating is off by default, can be turned on once the updater is ready (SET-05.h), and turning it on or off records msg:autoUpdateOn or msg:autoUpdateOff in History. | — |
| SET-05.v | backlog | While an update applies, the page asks for its progress at the interval in DEF-01 and gives up with Update failed after the time in DEF-01; while the page is shown it asks for the update status at the status interval in DEF-01, and reloads after the delay in DEF-01 if it never saw the restart. | — |
| SET-05.w | backlog | The app checks that the updater is ready at start and at the interval in DEF-01; the updater is ready when its health answer is OK within the time in DEF-01. | — |
| SET-06 | backlog | Site Admin settings are kept in the database and are the same on every device. | — |

| SET-06.c | backlog | Settings > Site Admin has Password requirements: the minimum length and the minimum number of capital letters, lowercase letters, numbers and special characters (defaults, and the floor each may not go below, are in DEF-01).
